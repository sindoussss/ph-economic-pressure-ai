## The findings, and what changed

Every headline is a null, and that is the result rather than a disappointment.

| Target | Setup | Verdict |
|---|---|---|
| RON95 fuel | 1-month forecast | efficient |
| USD/PHP | 1-month forecast | efficient |
| YoY inflation | 1-month forecast | efficient |
| MoM inflation, headline and food | nowcast | no better than naive |
| Electricity CPI | nowcast, driver-only | no better than naive |
| Transport CPI | nowcast, driver-only | rejected twice, preliminary-data artifact and fails against the mean |
| Google Trends search interest | nowcast | adds nothing on either target |

**Nothing in the repository survives multiple-testing correction.** Across the declared family
of 24 tests, `survive_bonferroni` and `survive_bh_only` are both empty. Four results land under
a nominal 0.05 against 1.2 expected by chance, and two of those four favour the naive baseline.

The two corrections that moved the science since `v2.0.0`:

**The baseline pool was missing the historical mean.** Adding it turns every month-on-month
positive into a null. A mean-reverting series makes the historical mean beat a random walk by
construction, so a protocol that omits it manufactures edges. The size study quantifies the
damage: on simulated data containing no signal at all, the mean-free protocol returns a
significant "edge" in 99.7% of replications at rho = 0 and n = 151, against a nominal 5%.

**The audit was not paying for its own selection.** `verdict_from_panel` assigned
`predictable` on a bare `dm_p < 0.05`, but it takes the BEST of four candidate methods and
judges that maximum, so it must correct for k = 4. Fuel had been reading `predictable` at
dm_p 0.0337 while the repository's own multiple-testing artifact already listed it under
`survive_neither`. Corrected, all three audit targets read `efficient`, which is what the
manuscript had said throughout.

One exploratory finding is disclosed and deliberately not promoted: a Ridge edge on the fuel
panel, +12.1% in sample, which survives neither correction and was never predeclared. It is
registered as `CLM-FUEL-EXPLORATORY-001`, and since 2026-08-20 it has a preregistered
confirmatory protocol that records why it cannot be confirmed here: roughly ninety-five monthly
predictions are needed against the seventeen available, about eight years.

## Reproducibility, tested rather than asserted

A cold reproduction was run on 2026-08-20: fresh `git clone` from GitHub, a new virtual
environment created from `requirements.txt` alone, then `python -m ph_economic_ai.benchmark.run`.

The environment resolved to the exact pins with no intervention, and two files out of the whole
artifact set differed, neither carrying a value:

    accuracy_report.json    identical once `generated_at` is removed
    multiple_testing.json   identical once `generated_at` is removed; raw diff is line endings

Every figure regenerated byte-identically.

Two honest limits. It ran on the same operating system, so it demonstrates a clean-environment
rebuild rather than cross-platform reproducibility. And the first attempt failed at
`python -m venv`, before any repository code ran, because the working path was 163 characters
against Windows' 260-character limit. **Clone to a short path on Windows.**

## Controls that keep this honest

- `benchmark/manuscript_check.py` cross-checks every manuscript, defence note and README
  against the committed artifacts, and reports `consistent` at this tag.
- Eight dated preregistration protocols under `docs/preregistration/`.
- Provenance sidecars with sha256 on all 24 committed data CSVs.
- Selection-holdout, HAC-corrected Diebold-Mariano, Bonferroni and Benjamini-Hochberg over the
  declared family, and per-target minimum detectable effects for every null.
